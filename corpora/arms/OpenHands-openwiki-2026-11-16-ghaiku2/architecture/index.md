# Files

- [Agent Controller and Step Loop](agent-controller.md) - How AgentController drives an agent one step at a time, reacts to events, enforces iteration and budget limits, detects stuck loops, gates actions behind confirmation, and hands work to delegate agents.
- [Agents, Prompting, and Delegation](agents-and-prompting.md) - The Agent base contract and registry, the CodeAct and browsing agents that ship in the agent hub, how their tool sets are gated by configuration, how tool calls become actions, and how prompts are assembled.
- [Configuration Model](configuration.md) - How OpenHandsConfig is built from config.toml, environment variables, and CLI arguments, how named LLM and agent sections are parsed, what the sub-configs control, and where the loading precedence is defined.
- [Event Stream, Actions, and Observations](event-stream.md) - The EventStream publish-subscribe hub that connects the agent controller, runtime, and server; the Action and Observation event model; how events are persisted, redacted of secrets, dispatched to subscribers, and read back.
- [Git Provider Integrations and MCP](integrations-and-mcp.md) - How OpenHands talks to GitHub, GitLab, and Bitbucket through per-provider services and a ProviderHandler facade, how provider tokens are exposed to the sandbox and masked in the event stream, how the MCP client attaches external tool servers to agents, and how OpenHands exposes its own MCP server for pull-request creation.
- [LLM Layer, Routing, Metrics, and Retries](llm-layer.md) - How OpenHands wraps LiteLLM in an LLM class that adds retries, cost and token accounting, function-calling emulation for models without native tool calls, and prompt-caching checks; how LLMRegistry shares named LLM instances; how RouterLLM selects among several models; and how the async and streaming variants are built.
- [Memory, Condensation, and Microagents](memory-and-context.md) - How the conversation history is turned into the bounded View the agent sees (condensers, condensation events, and the condenser pipeline), how Memory recalls workspace context and keyword-triggered microagent knowledge into the event stream, and how repository, global, and user microagents are discovered and loaded.
- [System Architecture Overview](overview.md)
- [Runtime and Sandbox Execution](runtime-sandbox.md) - The Runtime abstraction that subscribes to the event stream and executes agent actions; the action execution server and client protocol; the docker, local, remote, kubernetes, and CLI runtime implementations; runtime selection; timeouts, one-action-at-a-time execution, confirmation and rejection handling; and the plugins that a runtime installs.
- [Security Analysis and Action Gating](security-analysis.md) - How each agent action is assigned a risk level by a pluggable security analyzer (Invariant policy checks or the LLM's own risk field), how the controller turns that risk and the confirmation mode into an AWAITING_USER_CONFIRMATION pause, how the user's decision resumes or cancels the action, and where the sandbox refuses to run an unconfirmed or rejected action.
- [Server, Sockets, and Conversation Sessions](server-sessions.md) - How the OpenHands web server is assembled (Socket.IO wrapping a FastAPI app), how REST routes start and stop conversations, how a browser socket joins a conversation and replays its event log, how the conversation manager runs one agent loop per conversation with a per-user concurrency cap and idle cleanup, and the WebSession and AgentSession objects that hold the runtime, memory, and controller for a conversation.
- [Storage, Persistence, and Secrets](storage-persistence.md) - The FileStore abstraction and its local, in-memory, S3, Google Cloud, and webhook backends; the on-disk layout of conversations, events, and per-user settings and secrets; the conversation, settings, and secrets store interfaces and their file implementations; and what is and is not protected at rest.
