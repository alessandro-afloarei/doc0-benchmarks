# OpenHands Repository Quickstart

OpenHands is an AI software-engineering agent. A user gives it a task, the agent plans and calls tools, and every tool call runs in an isolated sandbox whose result feeds the next decision. This repository holds the whole system: the Python backend that runs the agent, the React web application, the enterprise hosted layer, the evaluation harness, the containers, and the docs. Start with the table below to find the page for your task. Read only the page you need; each one links to its neighbors.

## What is where

| Path | Contents |
| --- | --- |
| `openhands/` | The Python backend: `controller/` (agent loop), `events/` (event stream), `agenthub/` (agents), `runtime/` (sandboxes), `server/` (web API and sockets), `llm/` (model calls), `memory/` and `microagent/` (context and instructions), `storage/` (persistence), `core/` (config and entry helpers), `cli/`, `resolver/`, `security/`, `integrations/`, `mcp/` |
| `frontend/` | The React and Vite single-page web application |
| `openhands-ui/` | The shared `@openhands/ui` component library |
| `enterprise/` | The hosted SaaS layer on top of the backend: auth, billing, integrations, migrations, callbacks |
| `evaluation/` | Benchmark runners (`benchmarks/`), shared harness (`utils/`), and integration tests |
| `tests/` | Backend pytest suites: `unit/`, `runtime/`, and `e2e/` |
| `containers/` | Dockerfiles, build scripts, and the development container |
| `kind/` | Sample Kubernetes manifests and a kind cluster definition |
| `docs/` | The published documentation (Mintlify `docs.json`, `usage/`, and the OpenAPI spec `openapi.json`) |
| `microagents/` | Built-in microagent instructions shipped with the package |
| `.openhands/` | Repository-level instructions for agents working in this repo |
| `dev_config/` | Ruff and mypy configuration and the pre-commit config for Python |
| `third_party/` | Runtime and container assets (`third_party/runtime`, `third_party/containers`) |
| `openwiki/` | This generated wiki |

## Common commands

<!-- openwiki: broken internal link [/openwiki/operations/development-and-testing.md] link "/openwiki/operations/development-and-testing.md" is root-absolute, which no real consumer resolves against the repository root (not a coding agent reading the page, not GitHub's Markdown renderer, not a local viewer); use a path relative to this file instead. These come from the Makefile and the package configuration. See [Development, Testing, and Quality Gates](/openwiki/operations/development-and-testing.md) for the details.

- Install dependencies: `make build` (Poetry dependency groups for the backend, plus the project's build steps).
- Install the git hooks: `make install-pre-commit-hooks`.
- Run the application locally: `make run`. Run the container image: `make docker-run`.
- Run backend unit tests: `poetry run pytest ./tests/unit`, the form CI uses (with `--forked -n auto`).
- Run frontend checks: `cd frontend && npm run lint` and `npm run test`.
- Run one task headless: `python -m openhands.core.main -t "<task>"`, or use the `openhands` command for the interactive CLI.
- Regenerate the public API spec: `scripts/update_openapi.py` rewrites `docs/openapi.json` from the FastAPI app, keeping the existing `servers` entries and saving a backup.

## Conventions that matter

- The controller, event stream, runtime, and LLM layer are the stable seams. Most changes land in one of them and are visible through the event stream.
- Every model call goes through `LLM`, and every sandbox action goes through the runtime. A change to either affects all agents and all entry points.
- The CLI and the web server build the same components through the same factories in `openhands/core/setup.py`, but the CLI runs its own loop, so a change to `run_controller` does not change the CLI by itself.
