- [Celery App, Configuration, Loaders and Task Registry](application.md) - How the Celery application object lazily finalizes, reads and normalizes configuration, registers tasks (including deferred decorators and shared_task), autodiscovers task modules through loaders and fixups, and how the Django fixup hooks in.
- [Beat Scheduler and Schedules](beat-scheduler.md)
- [Canvas: Signatures, Chains, Groups and Chords](canvas-workflows.md) - How Celery composes tasks into workflows — Signature dicts, chain preparation (reverse-ordered chain header, group-to-chord uplift), group and chord execution, chord completion through result backends, error propagation (including the nested-chain chord-body fix), stamping and built-in tasks.
- [Command-Line Interface](cli.md) - How the celery umbrella command is built with Click — early pool monkey-patching, global options and app discovery, subcommand registry and plugins, preload options, worker/beat startup, detaching, and celery multi node management.
- [Concurrency Pools](concurrency-pools.md) - The worker's execution pool abstraction (BasePool) and its implementations — prefork on billiard's AsynPool, solo, threads, eventlet and gevent — including how the worker builds a pool, how requests are submitted and traced in child processes, and how timeouts, termination and lost workers are handled.
- [Events, Remote Control and Monitoring](events-and-monitoring.md) - How workers publish monitoring events (dispatcher, heartbeat), how clients consume and aggregate them (receiver, State, snapshots), how worker-to-worker sync works (mingle, gossip, election), and how the pidbox remote-control channel implements inspect/control commands such as revoke, rate_limit and pool_grow.
- [Architecture Overview](overview.md) - System-level map of Celery 5.6 — the app object, producer-side publishing through AMQP/kombu, the worker's bootstep-driven consumer and pool, result backends, beat, events and remote control — with the global state helpers (current_app, proxies) that tie them together.
- [Result Backends and AsyncResult](result-backends.md) - How Celery stores and retrieves task state and results — backend selection by URL, the Backend/KeyValueStore base classes, result metadata and exception serialization (including its security guard), retries, how AsyncResult/GroupResult wait (polling vs pub/sub drainers), chord counting hooks and the main concrete backends (Redis, RPC, database).
- [Message Signing and Security](security.md) - How Celery's optional message-signing 'auth' serializer works (RSA-PSS signatures, X.509 certificate store, setup_security preconditions), the serialization trust model (accept_content, pickle risk), and other security guards such as result-backend exception validation and secret masking.
- [Task Class, Publishing and Routing](tasks.md) - The Task base class and its execution options, the publishing path from Task.apply_async to Celery.send_task to AMQP message creation, queue routing (task_routes, Router, Queues), native delayed delivery, eager execution, retries and autoretry, task replacement and add_to_chord.
- [Worker: Bootsteps, Consumer and Request Handling](worker.md) - How a Celery worker is assembled and run — the bootstep dependency framework, WorkController and Consumer blueprints, the message-to-strategy-to-Request-to-pool path, ETA and rate-limit scheduling, prefetch/QoS, the event loops, connection-loss recovery, autoscale, global worker state, and ack/revoke/expiry handling.
