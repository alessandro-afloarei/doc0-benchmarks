# Files

- [ASAR archive support](asar-archives.md) - How Electron reads .asar archives — the native header parser and file extraction in shell/common/asar, the Node fs/child_process/module patches in lib/node/asar-fs-wrapper.ts, file:// loading through AsarURLLoaderFactory, unpacked files, per-file and header integrity validation, and the fuses and environment variables that control ASAR behavior.
- [Fuses and build flags](fuses-and-build-flags.md) - The three layers of Electron feature control — GN build flags compiled into the binary (buildflags/), runtime fuses stored in a sentinel-marked byte array that packagers can flip in the shipped executable (build/fuses/), and Chromium base::Feature defaults set by Electron's feature list initialisation.
- [IPC between main and renderer](ipc.md) - End-to-end flow of Electron IPC — ipcRenderer send/sendSync/invoke/postMessage over the ElectronApiIPC mojom interface, dispatch through Session into ipc-dispatch.ts with frame/WebContents/global ipcMain priority, invoke/handle replies, main-to-renderer messages via WebFrameMain and ElectronRenderer, internal channels used by Electron itself, service-worker IPC, and MessagePortMain.
- [Sessions, protocols and networking](sessions-protocols-and-networking.md) - How Electron's session API maps to ElectronBrowserContext storage partitions, how custom and intercepted protocols are registered and served (registerSchemesAsPrivileged, protocol.handle, ProtocolRegistry, ElectronURLLoaderFactory), how webRequest hooks into ProxyingURLLoaderFactory, how net.request / net.fetch use SimpleURLLoader, and how permission handlers default.
- [Utility processes](utility-process.md) - How utilityProcess.fork launches a Chromium utility process hosting a Node.js environment — option validation in lib/browser/api/utility-process.ts, UtilityProcessWrapper launching NodeService via ServiceProcessHost, the dedicated postMessage pipe and process.parentPort, network access through a browser-provided URL loader factory, stdio piping, and spawn/exit/error lifecycle.
- [The webview tag and guest views](webview-guests.md) - How Electron's <webview> works — a custom element with a shadow-root iframe defined in the embedder's main world, internal IPC to guest-view-manager.ts which creates a guest WebContents and attaches it as an inner WebContents of that iframe, inherited security preferences, allowlisted method/property proxying, event forwarding, and lifetime management.
- [Windows, views and WebContents](windows-and-web-contents.md) - How Electron's window and page objects are layered — BaseWindow over platform NativeWindow implementations, BrowserWindow as BaseWindow plus a WebContentsView, the View tree, the WebContents API wrapper and its session/type selection, WebFrameMain identity across frame swaps, the close/destroy lifecycle and WindowList, and window.open handling via setWindowOpenHandler and guest-window-manager.
