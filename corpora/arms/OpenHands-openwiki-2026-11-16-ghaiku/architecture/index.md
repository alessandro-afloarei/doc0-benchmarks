# Files

- [Agent Controller and Step Loop](agent-controller.md) - How AgentController turns events into agent steps, gates each step on agent state, limits and stuck detection, and handles finish, error, and delegate paths.
- [Agents, Tools, and Microagents](agents-and-tools.md) - How agents are registered and selected by name, how the CodeAct agent turns model output into actions through its tool set and pending queue, and how microagent prompts are loaded and classified.
- [Configuration System](configuration.md) - How OpenHands assembles its OpenHandsConfig from config.toml, environment variables, and CLI arguments, including precedence, the sub-config schemas for LLM, agent, sandbox, security, condenser, MCP, and model routing, and where settings.json fits.
- [Event Model and Event Stream](event-stream.md) - The Action and Observation event taxonomy, how events are assigned IDs, redacted, persisted in page-based files, delivered to subscriber thread pools, and searched or filtered for replay and UI display.
- [LLM Layer](llm-layer.md) - How OpenHands wraps LiteLLM in the LLM class, applies retries and metrics, emulates function calling for models without native tool support, registers shared LLM services, and routes calls between models through RouterLLM.
- [System Architecture Overview](overview.md) - The top-level map of OpenHands, showing the Python agent core, the FastAPI and Socket.IO server, the React web app, the CLI, the enterprise SaaS layer, and the evaluation harness, and how they share the event stream, the runtime, and the configuration model.
- [Runtime Abstraction and Execution Backends](runtime.md) - How the Runtime base class turns events into sandboxed execution, how backends (Docker, local, remote, Kubernetes, CLI) provide the sandbox, and how the action execution server inside the sandbox runs commands, file operations, browser actions, and MCP tools.
- [Server, Routes, and Conversation Management](server-and-conversations.md) - How the OpenHands server exposes REST routes and a Socket.IO channel, how a ConversationManager starts and tracks per-conversation agent sessions (standalone or nested in Docker), how WebSession and AgentSession wire a controller and runtime together, and how user authentication, settings, and secrets are pluggable.
