# Files

- [IPC: ipcMain, ipcRenderer, MessagePorts](ipc.md) - End-to-end explanation of how renderer-to-main messages travel from ipcRenderer through a Mojo interface and a C++ handler into the main-process JS dispatcher, including invoke/handle, sendSync, internal channels, MessagePorts and service-worker IPC.
- [JavaScript Bundles and Internal Module Loading](js-bundles-and-internal-modules.md) - How Electron's TypeScript in lib/ is compiled by webpack into eight per-process bundles, embedded into the binary with js2c, loaded by name through Node, and how the lazily populated 'electron' module is assembled from module lists.

- [Node.js and Chromium Event Loop Integration](node-chromium-integration.md) - How Electron embeds Node.js into Chromium processes - the shared V8 isolate, per-process Node environments, the libuv embed thread that wakes Chromium's message loop, microtask policy differences, and how the main process blocks until app code has loaded.
- [Process Model and Startup Sequence](process-model.md) - How an Electron executable boots - the main() entrypoints, run-as-node mode, ElectronMainDelegate and its content clients, the ordered BrowserMainParts hooks, and the Browser object's launch and quit lifecycle that hand control to the app's JavaScript.
- [Renderer, Preload Scripts, Sandbox and Context Isolation](renderer-preload-and-isolation.md) - Renderer-process runtime in Electron - how sandboxed and non-sandboxed renderer clients differ, how preload scripts are delivered and executed, how the isolated world and contextBridge work, and how the preload realm and web workers are initialized.
- [Sessions, Protocols, Network and Permissions](sessions-protocols-and-network.md) - How Electron models sessions on top of BrowserContext partitions, routes requests through custom protocol handlers and the webRequest proxying URL loader factory, exposes the net module, and decides web and device permissions through session-level handlers.
- [Utility Processes, Node Service and ASAR Archives](utility-processes-and-asar.md) - How utilityProcess.fork launches a sandbox-free Node.js child through the NodeService Mojo service and parent-port messaging, how child_process.fork reuses the binary in run-as-node mode, and how ASAR archives are virtualized in Node's fs, Chromium's loaders, and verified by integrity hashes.
- [WebContents, Windows and Views](web-contents-and-windows.md) - How the WebContents API object wraps Chromium's content::WebContents, how BrowserWindow/BaseWindow, WebContentsView and View compose a native window with platform backends, and how window.open, popups and <webview> guests are created and governed.
