## Overview

fd builds with plain cargo; the Makefile adds completions and an install target, and a GitHub Actions workflow (`CICD.yml`) lints, tests, and packages release archives and Debian packages for fourteen targets. A release is cut by bumping the version on a branch, merging it, and pushing a `v*` tag, which makes CI publish the artifacts.

Sources: [Makefile:1-52](repo://Makefile#L1-L52), [.github/workflows/CICD.yml:1-19](repo://.github/workflows/CICD.yml#L1-L19), [doc/release-checklist.md:35-51](repo://doc/release-checklist.md#L35-L51)

## Cargo features and profiles

### Features

| Feature | Default | Effect |
| --- | --- | --- |
| `completions` | yes | Pulls in `clap_complete` and enables the hidden `--gen-completions` option |
| `use-jemalloc` | no | Uses `tikv-jemallocator` as the global allocator on supported targets |
| `base` | no | Alias for `use-jemalloc` |

Sources: [Cargo.toml:94-98](repo://Cargo.toml#L94-L98), [src/main.rs:114-129](repo://src/main.rs#L114-L129)

jemalloc is used for speed but is excluded on Windows, Android, macOS, FreeBSD, OpenBSD, illumos, 32-bit musl and riscv64. The target condition appears twice, on the dependency in `Cargo.toml` and on the `#[global_allocator]` in `src/main.rs`, and the two must be kept in sync. On aarch64 Linux, `Cross.toml` passes `JEMALLOC_SYS_WITH_LG_PAGE=16` into the cross build, configuring jemalloc for 2^16-byte (64 KiB) pages (fd issue 1085).

Sources: [Cargo.toml:65-71](repo://Cargo.toml#L65-L71), [src/main.rs:38-54](repo://src/main.rs#L38-L54), [Cross.toml:1-6](repo://Cross.toml#L1-L6)

### Profiles and toolchain

The crate uses the 2024 edition and requires Rust 1.90.0 (`rust-version`). The release profile enables LTO, strips the binary and uses one codegen unit. The dev profile keeps only line tables for fd and no debug info for dependencies; a `debugging` profile inherits from dev with full debug info. `.cargo/config.toml` links the C runtime statically on Windows MSVC targets, so `fd.exe` does not need the vcruntime DLL.

Sources: [Cargo.toml:16-21](repo://Cargo.toml#L16-L21), [Cargo.toml:79-92](repo://Cargo.toml#L79-L92), [.cargo/config.toml:1-9](repo://.cargo/config.toml#L1-L9)

## Makefile

`make` builds `target/release/fd` with `cargo build --profile release --locked`. `make completions` fills `autocomplete/` with bash, fish and PowerShell completions generated by the binary, plus the zsh `_fd` and the `fdfind` variants copied from `contrib/completion/`. `make install` installs the binary, the completions and the man page under `$(DESTDIR)$(prefix)`, with `prefix=/usr/local` by default.

Sources: [Makefile:1-52](repo://Makefile#L1-L52)

```bash
make
make completions
sudo make install prefix=/usr
```

Sources: [Makefile:1-12](repo://Makefile#L1-L12), [Makefile:44-52](repo://Makefile#L44-L52)

## Continuous integration

### Jobs

The workflow runs on pull requests, pushes to `master`, every tag, and on demand.

Sources: [.github/workflows/CICD.yml:7-14](repo://.github/workflows/CICD.yml#L7-L14)

| Job | Does |
| --- | --- |
| `crate_metadata` | Reads name, version, maintainer, homepage and MSRV with `cargo metadata` |
| `ensure_cargo_fmt` | `cargo fmt -- --check` |
| `lint_check` | `cargo clippy --all-targets --all-features -- -Dwarnings` on stable |
| `min_version` | clippy and `cargo test --locked --all-features` on the MSRV |
| `build` | Builds, tests and packages each target in the matrix |
| `winget` | Publishes the Windows MSVC zip to Winget, for `v*` tags |

Sources: [.github/workflows/CICD.yml:19-84](repo://.github/workflows/CICD.yml#L19-L84), [.github/workflows/CICD.yml:86-115](repo://.github/workflows/CICD.yml#L86-L115), [.github/workflows/CICD.yml:299-309](repo://.github/workflows/CICD.yml#L299-L309)

### The build matrix

Linux targets (x86_64, i686, aarch64 and armhf, each with glibc and musl) are built with `cross` v0.2.5; macOS (Intel and Apple silicon) and Windows (MSVC for i686, x86_64 and aarch64, plus x86_64 GNU) are built with cargo on native runners. Every target runs `build --locked --release` and then the tests; for ARM targets only the binary's unit tests run (`--bin=fd`).

Sources: [.github/workflows/CICD.yml:94-198](repo://.github/workflows/CICD.yml#L94-L198)

### Packaging

After testing, `make completions` runs and the job assembles `fd-v<version>-<target>` with the binary, README, licenses, changelog, man page and `autocomplete/` directory, packed as `.tar.gz` (or `.zip` on Windows). On Ubuntu runners, `scripts/create-deb.sh` also builds a Debian package. For tags matching `v[0-9]*`, the archives and packages are attested and attached to the GitHub release.

Sources: [.github/workflows/CICD.yml:200-297](repo://.github/workflows/CICD.yml#L200-L297)

## Debian packages

`create-deb.sh` stages a package tree: the binary as `/usr/bin/fd` plus an `fdfind` symlink, the gzipped man page, bash, fish and zsh completions for both names, the docs, a copyright file and a `DEBIAN/control` file, then runs `fakeroot dpkg-deb --build`. musl builds are named `fd-musl` and glibc builds `fd`; each conflicts with the other and with Debian's own `fd-find`, and both declare `Provides: fd`. The architecture comes from the target triple (`amd64`, `arm64`, `armhf`, `i686`).

Sources: [scripts/create-deb.sh:1-66](repo://scripts/create-deb.sh#L1-L66), [scripts/create-deb.sh:108-135](repo://scripts/create-deb.sh#L108-L135)

## Release process

### Version bump

`scripts/version-bump.sh <version>` performs the first part of the checklist: it switches to a `release-<version>` branch, sets the version in `Cargo.toml`, writes the current MSRV into the README's install note, and renames the changelog's "Upcoming release" heading to the version. `cargo build` then updates `Cargo.lock`, which must be committed as well.

Sources: [scripts/version-bump.sh:1-21](repo://scripts/version-bump.sh#L1-L21), [doc/release-checklist.md:6-18](repo://doc/release-checklist.md#L6-L18)

### Checks and publishing

1. Install the new build with `cargo install --locked -f --path .` and confirm `fd --version`.
2. Review `-h`, `--help` and the man page, and refresh the README's option list with `gawk -i inplace -f scripts/update-help.awk README.md`.
3. Push, wait for CI, and run `cargo publish --dry-run`.
4. Fast-forward merge the release branch, then `git tag vX.Y.Z` and push the tag, which triggers deployment.
5. Create the GitHub release from the tag with the changelog section as notes, and check that archives and Debian packages appear.
6. Run `cargo publish` from a clean clone.
7. Add a new "Upcoming release" section with Features, Bugfixes, Changes and Other subsections to the top of `CHANGELOG.md`.

Sources: [doc/release-checklist.md:20-69](repo://doc/release-checklist.md#L20-L69)

Contributors add their entry to that "Upcoming release" section in each pull request that changes behavior, in the form `- Short description, see #123 (@user)`.

Sources: [CONTRIBUTING.md:30-46](repo://CONTRIBUTING.md#L30-L46)
