# Files

- [Concurrency Pools](concurrency-pools.md) - The worker's execution pools — the BasePool contract, the prefork pool built on billiard with the non-blocking AsynPool integrated into the event loop, child process initialization, scheduling strategies and time limits, the eventlet/gevent green pools, the thread and solo pools, pool selection and monkey-patching, and the autoscaler.
- [Worker Consumer](consumer.md) - The worker's Consumer (celery/worker/consumer/) — its bootstep blueprint (Connection, Mingle, Events, Gossip, Heart, Control, Tasks, DelayedDelivery, Evloop, Agent), message dispatch to task strategies, prefetch/QoS management including quorum queues and disable-prefetch, rate-limit buckets, the asynloop/synloop event loops, and connection-loss recovery.
- [Remote Control and Inspection](remote-control.md) - Celery's broadcast remote-control system — the client-side app.control (Control, Inspect, broadcast, reply flattening), the kombu pidbox mailbox, the worker-side Pidbox consumer step and Panel command registry, the built-in inspect and control commands (revoke, rate_limit, time_limit, pool resize, autoscale, queues, shutdown, events), and how the CLI exposes them.
- [Task Request Lifecycle in the Worker](request-lifecycle.md) - Step-by-step path of a task message inside the worker — strategy dispatch, Request creation, revocation/expiry checks, ETA and rate-limit scheduling, pool submission, acceptance and acknowledgement rules (acks_late, acks_on_failure/timeout, reject_on_worker_lost), time limits, failures and termination, and the global worker state that tracks reserved and active requests.
- [Worker Architecture and Bootsteps](worker-architecture.md) - How a Celery worker process is assembled and run — the bootsteps Blueprint/Step/StartStopStep dependency system, WorkController initialisation and its default components (Timer, Hub, Pool, Beat, StateDB, Consumer, Autoscaler), the celery.apps.worker CLI subclass, OS signal handling, and warm, soft and cold shutdown semantics.
