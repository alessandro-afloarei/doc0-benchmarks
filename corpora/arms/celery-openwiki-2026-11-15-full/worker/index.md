# Files

- [Worker Bootsteps and WorkController](bootsteps-and-workcontroller.md) - How a Celery worker process is assembled and run — the bootsteps dependency-graph mechanism, the WorkController blueprint (Timer, Hub, Pool, Beat, StateDB, Consumer, Autoscaler), the apps.worker.Worker program layer, worker-global state, and warm/cold/soft shutdown and signal handling.
- [Concurrency Pools and Autoscaling](concurrency-pools.md) - The worker execution pools in celery.concurrency — BasePool contract, prefork (billiard Pool / AsynPool with non-blocking pipes and fair scheduling), threads, solo, eventlet and gevent green pools, custom pools — child-process initialisation, time limits, and the autoscaler.
- [Worker Consumer and Event Loop](consumer.md) - The worker's Consumer — its bootstep blueprint (Connection, Mingle, Events, Gossip, Heart, Control, Tasks, DelayedDelivery, Evloop, Agent), broker connection retry and recovery, prefetch/QoS management and reduction after reconnects, the asynloop/synloop event loops, message dispatch to task strategies, rate-limit buckets and unknown/invalid message handling.
- [Native Delayed Delivery and Quorum Queues](delayed-delivery-and-quorum-queues.md) - How Celery supports RabbitMQ quorum queues — queue-type configuration, quorum-queue detection, disabling global QoS, the DelayedDelivery consumer bootstep that declares kombu's native delayed-delivery topology and binds application queues, and how send_task routes ETA/countdown tasks through the celery_delayed_27 exchange.
- [Remote Control and Inspection](remote-control.md) - Celery's broadcast remote-control system — the client API (app.control, Inspect, broadcast), the kombu pidbox mailbox, the worker Control bootstep and Pidbox/gPidbox consumers, the Panel command registry with control and inspect commands (revoke, rate_limit, time_limit, pool_grow, autoscale, add_consumer, shutdown, stats, active, ...), and the celery inspect/control/status CLI.
- [Task Execution: Strategy, Request and Tracing](task-execution.md) - What happens to a task message inside a worker — the default strategy (protocol conversion, revocation, ETA and rate limiting), the Request object and its pool callbacks, acknowledgement semantics (early ack, acks_late, reject, requeue, worker lost, time limits), revocation and termination, and the tracer that runs the task, maps exceptions to states, dispatches callbacks and stores results.
