# Files

- [ASAR Archives and Module Loading](asar-and-module-loading.md) - How Electron loads application code from ASAR archives, how the fs and Node module resolver are patched to read from them, how the app entry is searched, and which fuses and integrity checks gate that loading.
- [Browser Main Process (shell/browser)](browser-main-process.md) - Responsibilities and internal structure of shell/browser, the C++ side of Electron's browser (main) process. Covers the startup and shutdown lifecycle, the Browser singleton, window creation through NativeWindow, the browser-side content client, network and protocol handling, and platform-specific code.
- [IPC Between Main, Renderer, and Utility Processes](ipc.md) - How ipcMain, ipcRenderer, MessagePorts, and WebContents messaging are implemented across lib/ and shell/. Covers the mojo transport, the browser-side dispatch of send, invoke, and sendSync to the JavaScript emitters, reply semantics, and the internal-versus-public channel split.
- [JavaScript API Layer (lib/)](js-api-layer.md) - How the TypeScript sources under lib/ implement the public Electron JavaScript API for each process type, how webpack bundles them into per-process init scripts compiled into the binary, and how they bind to the native objects exposed by shell/.
- [Native Bindings (gin_helper, gin_converters, shell/common/api)](native-bindings.md) - How C++ code in shell/ exposes objects and functions to JavaScript. Covers the linked-binding registration that lib/ modules call through process._linkedBinding, the gin Wrappable and EventEmitter pattern, the gin_helper template and dictionary helpers, and the gin_converters that map C++ types to V8 values.
- [Architecture Overview](overview.md) - High-level map of Electron as Chromium plus embedded Node.js, with a JavaScript API layer in lib/ over native C++ in shell/. Shows how the entry point, process types, native bindings, bundled JavaScript, and the Chromium/Node/V8 patch and build pipeline fit together.
- [Process Model and Startup](process-model.md) - How Electron starts and divides work across the browser (main) process, renderer, utility process, sandboxed renderer, preload realm, isolated renderer, and worker processes. Covers the entry points, the process type each runs as, and the per-process init modules in lib/ that set up Node.js and Electron APIs for each.
