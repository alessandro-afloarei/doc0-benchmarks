# Output, formatting, and terminal integration

Path printing is the default consumer of accepted search results. `src/walk.rs` owns buffering and lifetime, while `src/output.rs` renders each entry. With `-x`, `-X`, or `--list-details`, results instead go through [command execution](../workflows/command-execution.md); fd's ordinary path renderer does not render the child program's output.

## Ordering and latency

The plain-output receiver initially collects entries for up to 100 milliseconds by default. If the channel closes or the result limit is reached while still buffering, it sorts the buffered `DirEntry` values by their underlying paths before printing. If the deadline expires or the buffer grows beyond 1,000 entries, it flushes the buffer in arrival order and switches permanently to streaming. The hidden `--max-buffer-time` option overrides the time budget.

This gives small, fast searches tidy output without requiring every search to accumulate all matches. It does not guarantee globally sorted output, a stable first result, or deterministic traversal order. When streaming and no batch is immediately waiting, the receiver flushes stdout before waiting for more input. See [search pipeline](../architecture/search-pipeline.md) for the producer/channel topology.

## Choosing a path representation

`--absolute-path` changes search-root normalization; `--full-path` changes the string used for matching. Neither should be inferred from the other. The [patterns and paths page](../search/patterns-and-paths.md) explains this distinction.

For an implicit current-directory search, ordinary printing automatically strips `./`; NUL output and command execution retain it by default. `--strip-cwd-prefix` can change that policy, but it applies only when no search roots were supplied. Even when stripping is enabled, `DirEntry::stripped_path` keeps the original path if removing `./` would expose a leading dash, avoiding accidental downstream option interpretation.

Each normal record ends in a newline, or NUL with `-0`/`--print0`. Plain and colored renderers append the configured path separator to directory entries. A format template controls its own body and does not automatically acquire that trailing directory separator.

On Unix, uncolored, unformatted output to a pipe or file writes raw path bytes when no custom separator is active. This preserves invalid UTF-8 filenames. Terminal rendering, color, formatted output, and custom-separator rendering use string conversion and can replace invalid UTF-8. For machine consumption of ordinary paths, use:

```sh
fd --color=never --hyperlink=never -0 -t f -e rs | xargs -0 wc -l
```

The NUL terminator avoids ambiguity from embedded newlines; byte preservation still depends on the renderer conditions above.

## Shared format templates

`--format` uses the same `FormatTemplate` parser as execution templates. It recognizes the following transformations of a result such as `docs/guide.md`:

| Token | Result |
| --- | --- |
| `{}` | `docs/guide.md` |
| `{.}` | `docs/guide` |
| `{/}` | `guide.md` |
| `{//}` | `docs` |
| `{/.}` | `guide` |

Double braces escape literal braces. Text without placeholders remains fixed text, so `--format 'found'` prints that text for every result. Custom separators replace path components generated by placeholders; fixed text is preserved. Extension removal uses the final file stem, and a dotfile such as `.foo` retains its name.

```sh
fd -t f -e md --format '{//}: {/}'
```

The format branch takes priority over coloring. Hyperlink wrappers and newline/NUL record termination remain outside the format body. Unlike an execution template, an output format does not gain an implicit `{}` when none is supplied.

## Color, links, and safe terminal text

`--color=auto` requires terminal stdout, ANSI support, and no nonempty `NO_COLOR`. `always` and `never` override that choice. On Windows, ANSI support is tested through `nu_ansi_term`, with `TERM` as another enabling condition. When coloring is enabled, `LS_COLORS` is used if available; otherwise fd uses its built-in palette. Workers precompute entry styles before sending results, and each entry caches the style.

Hyperlinks default to `never`; `auto` follows the resolved colored-output setting, and `always` enables them explicitly. `print_entry` wraps rendered text with OSC 8 sequences if it can construct an absolute `file:` URL. The URL encoder percent-encodes unsafe and non-ASCII path bytes, uses a cached hostname on Unix, and maps Windows backslashes to URL slashes. If absolute-path conversion fails, the entry prints without a link.

Terminal filename text is passed through `maybe_sanitize` independently of whether color is active. It escapes control characters and selected invisible/bidirectional formatting characters as visible hexadecimal escapes while allowing tabs. Pipes/files skip this terminal escaping. This protects fd's terminal presentation against escape-bearing filenames; it does not transform command arguments or child output.

## Failure behavior and regression anchors

An individual entry write suppresses a `BrokenPipe` diagnostic, while other write failures print an error and return status 1. A failed stdout flush also returns status 1 without an additional message. Thus suppressing a broken-pipe message is not a guarantee that every pipe closure exits successfully.

Use `format`, `test_print0`, `test_custom_path_separator`, `test_strip_cwd_prefix`, `test_invalid_utf8`, and `test_hyperlink` in `tests/tests.rs` to check integrations. Unit tests in `src/fmt/`, `src/sanitize.rs`, and `src/hyperlink.rs` isolate template parsing, path transformations, terminal escape handling, and URL encoding. The integration harness normally sorts comparison lines, so ordering assertions need direct output inspection; see [development and testing](../development/build-test-release.md).
